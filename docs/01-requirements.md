## 1. О приложении

### 1.1. Назначение
Pulse Search — поисковая система с поддержкой семантического поиска и векторизации документов. Приложение позволяет индексировать веб-сайты и осуществлять поиск по их содержимому с учетом не только ключевых слов, но и смысла запроса.

### 1.2. Роли пользователей
- **Пользователь (гость):** ищет информацию, просматривает результаты, запрашивает похожие страницы.
- **Администратор:** добавляет сайты на индексацию, следит за статусом обработки, запускает переиндексацию.

### 1.3. Термины
- **Индексация** — процесс сканирования сайта, извлечения текста и построения поисковых индексов.
- **TF-IDF** — статистическая мера, используемая для оценки важности слова в контексте документа.
- **SBERT (Sentence Transformers)** — нейросетевая модель для построения векторных представлений (эмбеддингов) текста.
- **Эмбеддинг** — числовой вектор, отражающий семантический смысл текста.
- **Гибридный поиск** — комбинация TF-IDF и SBERT для ранжирования результатов.

### 1.4. Что уже умеет приложение (на момент начала лабы 2)
- Запуск в Docker (5 контейнеров: backend, frontend, postgres, redis, worker).
- Добавление сайта на индексацию через админ-панель (`/admin`).
- Сканирование до 10 страниц с сайта.
- Построение TF-IDF и SBERT-эмбеддингов.
- Поиск по индексированным страницам с выводом заголовков, URL и сниппетов.
- Просмотр похожих страниц (кнопка «Show similar pages»).
- Ручной запуск переиндексации через API (`/api/reindex`).

## 2. Требования к функционалу (FR-n) и ограничения (NFR-n)

### 2.1. Функциональные требования

| Номер | Формулировка | Приоритет | Состояние | Признак выполнения |
|-------|--------------|-----------|-----------|---------------------|
| **FR-1** | Пользователь может ввести поисковый запрос и получить список релевантных страниц. | Обязательно | Уже есть | Ввод запроса на главной странице возвращает непустой список результатов (если страницы проиндексированы). |
| **FR-2** | Пользователь может просмотреть сниппет (краткое содержание) для каждого результата поиска. | Обязательно | Уже есть | В результатах поиска отображается текст длиной до 200 символов. |
| **FR-3** | Пользователь может запросить список страниц, похожих на выбранный результат (семантическая близость). | Желательно | Уже есть | При нажатии «Show similar pages» отображается до 5 ссылок на похожие страницы. |
| **FR-4** | Администратор может добавить новый сайт на индексацию, указав его URL. | Обязательно | Уже есть | После ввода URL в админ-панели создается запись в БД и запускается задача Celery. |
| **FR-5** | Администратор может просмотреть статус индексации всех добавленных сайтов. | Обязательно | Уже есть | В админ-панели (или через API `/api/status`) отображается список сайтов с полями: URL, статус, количество страниц. |
| **FR-6** | Администратор может запустить переиндексацию всех данных (пересчет TF-IDF и эмбеддингов). | Обязательно | Уже есть | Вызов `POST /api/reindex` запускает задачу `recalculate_all`, после чего поиск работает корректно. |
| **FR-7** | Система может автоматически переиндексировать данные раз в сутки. | Желательно | Уже есть | В `tasks.py` настроен цикл с интервалом `REINDEX_INTERVAL = 86400` секунд. |
| **FR-8** | Пользователь может видеть статистику на главной странице: количество проиндексированных сайтов, страниц, время последней синхронизации. | Желательно | Уже есть | На главной странице отображаются 4 метрики (Sites Indexed, Pages Crawled, Last Sync, Search Queries). |
| **FR-9** | Система должна поддерживать поиск на русском и английском языках. | Обязательно | Уже есть | Токенизация выполняется через `pymorphy3` (RU) и `spaCy` (EN); поиск по русским и английским запросам возвращает результаты. |
| **FR-10** | Администратор может защитить админ-панель паролем (базовая HTTP-аутентификация). | Желательно | Уже есть | При переходе на `/admin` браузер запрашивает логин и пароль (Nginx + `.htpasswd`). |

### 2.2. Нефункциональные требования (ограничения)

| Номер | Формулировка | Как проверить |
|-------|--------------|---------------|
| **NFR-1** | Приложение должно запускаться в Docker-контейнерах (Docker Compose) на Windows, Linux или macOS. | Выполнить `docker compose up -d --build` — все 5 контейнеров переходят в статус `Up`. |
| **NFR-2** | Время ответа на поисковый запрос не должно превышать 5 секунд при количестве проиндексированных страниц до 100. | Замерить время выполнения `curl "http://localhost:8000/api/search?q=test"` — ответ должен прийти быстрее 5 секунд. |
| **NFR-3** | Система должна хранить пароли администратора в виде bcrypt-хэша (не в открытом виде). | Проверить содержимое `frontend/.htpasswd` — там должен быть хэш, а не чистый пароль. |
| **NFR-4** | Система должна использовать PostgreSQL с расширением `pgvector` для хранения эмбеддингов. | В `docker-compose.yml` используется образ `ankane/pgvector:latest`; в `init.sql` создается расширение `vector`. |
| **NFR-5** | Индексация одного сайта не должна блокировать работу пользователей (выполняется асинхронно через Celery). | Во время индексации сайта поиск по уже проиндексированным страницам продолжает работать. |

## 3. Пользовательские сценарии (US-n)

### US-1 (связан с FR-1, FR-2)
**Я как Пользователь** имею доступ к главной странице и проиндексированную базу данных.  
**Делаю:** ввожу запрос «docker» в поисковую строку и нажимаю «Search».  
**Получаю:** список из 10 результатов с заголовками, URL и сниппетами.

**Входные данные:** текстовый запрос (например, `docker`).  
**Выходные данные:** JSON-ответ с массивом объектов `{page_id, url, title, score, snippet}`.

**Пример:**
- Ввод: `docker`
- Ожидаемый результат: не менее 1 результата, в заголовке или сниппете которых встречается слово «docker».

**Обработка ошибок:**
- Если запрос пустой — возвращается пустой список (`{"results": [], "total": 0}`).
- Если ничего не найдено — отображается сообщение «Ничего не найдено».

---

### US-2 (связан с FR-3)
**Я как Пользователь** имею список результатов поиска.  
**Делаю:** нажимаю кнопку «Show similar pages» под одним из результатов.  
**Получаю:** список из 5 ссылок на страницы, семантически близкие к выбранной.

**Входные данные:** `page_id` выбранной страницы.  
**Выходные данные:** JSON-ответ `{"page_id": 1, "similar": [{id, url, title, score}], "total": N}`.

**Пример:**
- Ввод: `page_id = 1` (главная страница docker.com).
- Ожидаемый результат: список из 5 страниц, среди которых могут быть «Docker Products», «Docker Pricing FAQ» и т.д.

**Обработка ошибок:**
- Если у страницы нет эмбеддинга — возвращается ошибка 400 с сообщением «Page has no embedding. Please reindex the site.»
- Если страница не найдена — ошибка 404.

---

### US-3 (связан с FR-4, FR-5)
**Я как Администратор** имею доступ к админ-панели (после ввода логина и пароля).  
**Делаю:** ввожу URL `https://example.com` и нажимаю «Добавить сайт».  
**Получаю:** сообщение «Сайт успешно добавлен», запись появляется в списке сайтов со статусом `pending`, затем `processing`, затем `indexed`.

**Входные данные:** URL сайта (строка, валидный URL).  
**Выходные данные:** запись в БД (таблица `sites`), запуск задачи Celery `index_site`.

**Пример:**
- Ввод: `https://example.com`
- Ожидаемый результат: через 1–2 минуты статус сайта меняется на `indexed`, количество страниц > 0.

**Обработка ошибок:**
- Если URL невалидный — ошибка 422 (Pydantic validation error).
- Если сайт уже существует — ошибка 400 «Site already exists».

---

### US-4 (связан с FR-6)
**Я как Администратор** имею проиндексированные страницы, но поиск не работает (эмбеддинги не рассчитаны).  
**Делаю:** вызываю `curl -X POST http://localhost:8000/api/reindex`.  
**Получаю:** сообщение `{"status": "reindexing started"}`, через некоторое время поиск начинает работать.

**Входные данные:** HTTP POST-запрос без тела.  
**Выходные данные:** JSON-ответ `{"status": "reindexing started"}`.

**Обработка ошибок:**
- Если Celery-воркер не запущен — задача остается в очереди, но не выполняется (пользователь видит, что поиск не работает).

---

### US-5 (связан с FR-8)
**Я как Пользователь** открываю главную страницу.  
**Делаю:** ничего не ввожу, просто смотрю на экран.  
**Получаю:** статистику: количество сайтов, количество страниц, время последней синхронизации, количество запросов.

**Входные данные:** нет.  
**Выходные данные:** 4 метрики, полученные через `GET /api/status`.
